Decode a YubiKey's Yubico OTP, OATH, PIV, OpenPGP card and YubiHSM Auth traffic. FIDO2 and FIDO U2F stay on the WebAuthn page. USB and NFC are the same bytes. A pasted trace needs no reader. A PIN, an OTP key, an OATH seed and an API key are not saved unless the box next to that field is checked, and a PIN is never saved.

This is the static deployment. Decoding and the OATH calculator work here. Verifying an OTP with YubiCloud, and talking to a reader, need the API. A container does not see a key on the host unless the operator passes the device through.

Tip: click a pane's title to collapse/expand it.

Yubico OTP

Touch the key and it types the token. The public identity is the first twelve characters of a current 44-character OTP. The AES key decrypts the rest. The CRC is how a wrong key is recognised.

YubiCloud validation

The API key stays in this browser. The page signs the request and the API posts it. A BAD_OTP answer is still an answer.

OATH

The calculator needs no key. Six digits is what an authenticator shows. The applet trace is YKOATH: PUT builds an APDU and does not send it.

through the API; read-only

PIV

NIST SP 800-73. A certificate sits in tag 70 inside tag 53. GENERAL AUTHENTICATE is decoded and not performed. Paste the response, including the status word, or the command.

through the API; read-only

OpenPGP card

Application related data and the public key. There is no OpenPGP message here. A signature or a decipher is decoded and not performed.

through the API; read-only

YubiHSM Auth

This is the applet that authenticates to a YubiHSM 2. CALCULATE's 48 bytes are the session keys a host would hand to that HSM. This page does not open a session. The management key and the credential password are not saved.

through the API; read-only

Reader

The reader is the machine the API runs on. localhost on this pane is that machine. A container does not see a USB key unless the operator passes the device through. PC/SC is optional: if the library is not installed, listing readers says so and the API stays up.

The reader relay is off on this API. Set smartcardReaderEnabled: true in its env file to list readers and transmit. It is off by default because any APDU reaches the card, including a wrong-PIN VERIFY that blocks the PIN.

Challenge-response to an OTP slot. Over WebHID the page polls the key the way yubikit does and waits up to 15 seconds for a touch. Over CCID it sends SELECT and CALCULATE to the OTP application through the api's reader relay, which is how the slots answer over NFC, and works in Firefox. The keyboard OTP field on the first pane works in every browser.
