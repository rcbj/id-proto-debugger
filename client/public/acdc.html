ACDC — a credential verified by its issuer's history

Authentic Chained Data Containers (Trust over IP KERI Suite specification) carry no signature: a credential's SAID — the digest of its own bytes — is sealed by an iss event in the issuer's registry, and that event is anchored by a seal in an event of the issuer's KERI key event log, which is signed. Verifying one walks that chain, all of it in a CESR stream. This reads the version 1 generation the released libraries issue credentials in (signify-ts, the KERIA client vLEI uses); CESR version 2 messages are refused by name. Nothing on this page is stored.

Verify a Presentation
The issuer's KEL, the registry inception (vcp), the credential's iss (and rev), and the ACDC with its -I seal source triple, concatenated as KERIA or keri-ts sends them.
Optional: the JSON Schema the credential's s names. Its $id is checked to be its own SAID.
