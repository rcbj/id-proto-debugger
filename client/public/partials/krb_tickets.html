Ticket Cache & History

Every ticket this workflow has obtained, newest first, from every page — and Make active puts one back in use unchanged.

What "in use" means, what Make active does, and where the rows live

The list is every page's: the AS exchange's TGTs, the TGS exchange's service tickets, and the delegation page's S4U2Self evidence, delegated tickets and renewals all appear here. A row marked in use is one the workflow is holding right now, which is the cache half of this pane; the rest is what it held earlier.

Make active puts a ticket back in the live slot it belongs in, unchanged — same expiry, same flags, no re-issue — so two tickets can be compared, or one from before a configuration change returned to. An expired ticket can be activated too: the next exchange refusing it, and saying why, is more useful than this pane pretending it is not there. Which rows this page can activate depends on which slot it holds, and the kind is derived from the ticket's own service name (krbtgt/… is a TGT, by the protocol's definition) rather than from a label — a mislabelled ticket accepted into the TGT slot would fail a page later, naming something else.

Each row holds a session key, and whatever holds one can use the ticket. So this list obeys the same checkbox as the ticket cache does on the AS exchange page: it lives in sessionStorage unless keep the credential cache in localStorage is ticked, and unticking it purges the whole list on the spot. Capped at 100, oldest dropped first. That is the opposite of the Operations History pane below, which holds no key material and is therefore never purged with it.
