GNAP

About this page

Grant Negotiation and Authorization Protocol (RFC 9635). This page is a client instance. It builds a grant request, proves the client key with an HTTP message signature or a JWS, and shows what the authorization server answers. The private key stays in this browser. The API path forwards a request that is already signed. Mutual TLS is a property of the connection, so this page does not offer it.

Tip: click a pane's title to collapse/expand it.

Client key
About the client key

The key this client instance proves itself with. It is sent in the grant request (client.key) and every request is signed with it. The private key stays in this browser; the API path forwards a request that is already signed.

Authorization server
About the authorization server settings

Where the grant request goes and how its proof travels. Through the API, the debugger's server forwards a request this browser already signed; from this browser, the request is sent directly and needs the server to allow it (CORS). Mutual TLS is a property of the connection, so this page does not offer it.

Continuation
About continuation

A grant that is not finished at once returns a continue URI and token. Continue asks again, with the interact_ref when there was interaction; Revoke ends the grant. The access token's management URI rotates or revokes the token itself.

Signed call
What a signed call is for

Any other request proved with the same key: present the access token, introspect it as a resource server, or read /.well-known/gnap-as-rs. Introspection is signed by the resource server's key.
