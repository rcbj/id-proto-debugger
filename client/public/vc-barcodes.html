VC Barcodes — a credential printed on a physical document

Verifiable Credential Barcodes v1.0 (W3C Working Draft, 22 August 2026) puts a signed credential in a barcode on an ID card, a passport or a driver's licence, and signs it over what the document already prints in machine-readable form — the MRZ, the licence's own AAMVA PDF417 fields, or (Appendix B, informative) an ISO licence's data groups — so the same barcode copied onto a forged document does not verify. The proof is ecdsa-xi-2023: ecdsa-rdfc-2019 with a hash of that optical data appended. The credential is CBOR-LD 1.0 (registry entry 100), small enough for a QR code.

Where the published barcodes and the draft's prose disagree, this page follows the barcodes, which every implementation produces: base45 is RFC 9285, the CBOR-LD tag is 51997, and ecdsa-xi-2023 hashes with SHA-256 on P-384 too. Nothing on this page is stored, the issuer's key included.

Check the Status List

A TerseBitstringStatusListEntry expands (with the list length and purpose above) to a Bitstring Status List v1.0 entry. Verify fills it in; this fetches the status list credential it names from this browser, verifies that credential's proof (Data Integrity, or a VC JWT), decodes its GZIP bitstring and reports the entry's bit. A list whose server sends no CORS headers cannot be fetched by a page: paste it instead.

Issue a Barcode
MachineReadableZone: an ID card or travel document, the credential in a QR code. AamvaDriversLicenseScannableInformation: a driver's licence, the credential inside its PDF417. IsoDrivingLicenceMachineReadableInformation (Appendix B, informative and expected to be refined): an ISO/IEC 18013-2 licence, the credential in data group 11.
The Machine Readable Zone the document prints, one line per line. Every line is signed, each followed by a newline, in printed order.
The licence's PDF417 text without a credential. The issued credential is added to it as subfile ZZ, element ZZA.
The mandatory AAMVA fields the signature covers (protectedComponentIndex). A field left out can change without the barcode noticing.
The licence's data groups, one "DGn: contents" line each (text with \n \r \t \\ and \xNN escapes, or "hex:" and hex). The issued credential is put in DG11, replacing what is there.
The data groups the signature covers (the 2-byte protectedComponentIndex), each signed as "DGn" + base64url(contents) + newline in data-group number order. DG11 carries the credential, so it cannot be protected.
ecdsa-xi-2023 signs with P-256 or P-384. The key stays in this page; download it to keep it.
The issuer's P-256 or P-384 private key as a JWK: generated above, or pasted. It is never stored.
The credential's issuer. Generate fills in the key's did:key; the verification method defaults to did:key:z…#z….
Optional. A TerseBitstringStatusListEntry: the status lists' base URL and this credential's 32-bit index.
