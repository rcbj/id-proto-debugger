Predicate Queries — prove a claim, do not show it

A predicate asks the holder to prove something about a claim — age >= 18, birthdate_dateint <= 20081118 — instead of disclosing the claim. OpenID4VP 1.0's DCQL has no predicates: a claim's values is an exact match, best effort (section 6.4.1), and a wallet ignores a property it does not understand (section 6.1). This page composes a predicate query in one of two languages, shows the AnonCreds presentation request it maps onto, sends it to this debugger's wallet, and verifies what comes back.

Which parts are standard. DIF Presentation Exchange 2.1.1 and its Predicate Feature are standard, carried as a presentation_definition as the OpenID4VP drafts did — removed in 1.0. The DCQL form is this debugger's extension (x_debugger_predicates, honoured only when x_debugger_crit lists it). AnonCreds proves a range in zero knowledge; an ISO mdoc answers an age bound with the issuer's age_over_NN; SD-JWT VC, jwt_vc_json and ldp_vc cannot prove one, and a required predicate is then refused, never answered with the value. Nothing secret is stored: only the composed request (vcpred_request).

Compose a Predicate Query

Presentation Exchange 2.1.1 (DIF, standard) carried as presentation_definition, as the OpenID4VP drafts did and 1.0 no longer does; or DCQL (OpenID4VP 1.0) with this debugger's non-standard predicate extension, honoured only when marked critical.
 
The format the query asks for. anoncreds proves a range predicate in zero knowledge; di_vc is AnonCreds in the W3C form (anoncreds-2023); mso_mdoc answers an age bound with the issuer's age_over_NN; the others cannot prove a predicate and a wallet refuses a required one.
The Input Descriptor id (Presentation Exchange) or the credential query id (DCQL): letters, digits, _ and -.
Attribute names the holder discloses, comma separated. A claim a predicate is about must not also be revealed: that would defeat the predicate, and AnonCreds refuses it.
One per line, "attribute op integer" with op one of >= > <= < (AnonCreds p_type). In Presentation Exchange each becomes a field with predicate and a filter of type integer with minimum, exclusiveMinimum, maximum or exclusiveMaximum. AnonCreds proves over integer attributes only; a date is YYYYMMDD.
Adds a predicate "born on or before today minus N years" over a YYYYMMDD birth date attribute, the AnonCreds specification's convention for date predicates ("birth_dateint <= 20020116").

Presentation Exchange 2.1.1: "required" means the answer MUST be the boolean result; "preferred" means it SHOULD be, so a holder may answer with the value. This debugger's wallet does not fall back to the value: an unprovable preferred predicate is refused too.
Optional. An AnonCreds restriction: only a credential under this credential definition answers. In Presentation Exchange it is a field on $.cred_def_id with a const filter.

The Equivalent AnonCreds Presentation Request

Every query maps onto an AnonCreds presentation request: one requested attribute per claim, one requested predicate per bound (minimum → >=, exclusiveMinimum → >, maximum → <=, exclusiveMaximum → <). The mapping is this debugger's: neither OpenID4VP nor Presentation Exchange defines AnonCreds.

 
An AnonCreds presentation request as the AnonCreds specification defines it: name, version, nonce (decimal digits), requested_attributes and requested_predicates ({ name, p_type, p_value }). Read converts it into the query above; Prove answers it with the credential this browser holds, with no OpenID4VP around it.
 
Send It to the Wallet

An OpenID4VP Authorization Request carrying the query — as dcql_query, or as the drafts' presentation_definition — from a redirect_uri: Client Identifier that is this page, answered by fragment. The wallet (steps 1 and 2 of the presentation workflow) shows which predicates it proves and what it does not reveal, and the answer comes back here to be verified.

The OpenID4VP nonce. The AnonCreds nonce, which must be decimal digits, is derived from it by the wallet's documented rule (the nonce itself when it is digits, else the first 80 bits of its SHA-256).
The Authorization Request as a link to this debugger's wallet. Send opens it; the composed query and its nonce are kept (vcpred_request) so the answer can be checked against them.
 
Inspect a Returned Presentation

The AnonCreds request is rebuilt from the query above, the nonce and what the presentation reveals, and the CL proof is verified against it with anoncreds.js: every predicate the query asks for must be proven, at exactly its bound.

What the wallet answered. For DCQL, an object keyed by credential query id (OpenID4VP 1.0 section 8.1); for a presentation_definition, the presentation itself. An AnonCreds presentation, legacy JSON or the W3C form.
Presentation Exchange 2.1.1: which Input Descriptor the vp_token answers, in which format, at which JSONPath. Checked against the definition and the vp_token. Empty for DCQL.
The schema and credential definition (and, for a revocable credential, the registry definition, status list and tails) to verify with, as an AnonCreds bundle. Empty: the bundle this browser holds is used. A Verifier with no ledger needs these out of band.
 
Capability Advertisement (debugger extension)

No specification defines how a wallet or a Verifier says it can prove or verify predicates. This debugger uses x_debugger_predicates_supported, in the wallet's wallet_metadata (OpenID4VP 1.0 section 10, sent under request_uri_method=post) and in the Verifier's client_metadata. Both are labelled as an extension wherever they appear.

What this debugger's wallet advertises: the query languages it reads, the crit entries it understands, and per format how it proves a predicate.
